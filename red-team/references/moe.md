# 중간 라운드 다이어트 — MoE (옵트인)

> SKILL.md 의 「참고 문서」에서 참조된다. **`--lean` / `"moe": true` 를 켜려 하거나 켜진
> 상태를 이어받았을 때만 읽는다** — 기본은 꺼짐이고, 꺼져 있으면 이 문서는 필요 없다.

라운드 비용은 거의 고정이라 라운드 수만큼 선형으로 쌓인다(실측: 코드 게이트 9라운드
티켓에서 축 전체 × 9회). 그렇다고 "이번엔 필요 없어 보이는" 축을 빼는 판단은 게이트 절에
적힌 창립 사고 패턴이다. 그래서 이 모드는 **생략이 아니라 유예**로 설계됐다 — GO 는
언제나 전체 축 커버리지에서만 확정된다:

1. **라운드 1 = 전체 축.** 직전 라운드가 없으면 `--lean` 도 전체를 돈다(베이스라인 —
   어떤 축이 뜨거운지 데이터로 확인).
2. **중간 라운드 = core + 직전 라운드에서 regression 을 낸 축.** `--lean` 이 직전
   round.json 에서 결정적으로 계산한다 — 결함을 낸 축은 그 수정의 재검증 때문에 자동으로
   다시 켜진다. 사람도 모델도 "필요해 보이는가"를 판단하지 않는다.
3. **GO 후보 = top-up 으로 확정.** 축이 빠진 라운드의 GO 는 round.json 에
   `coverage: partial` 로 기록되고 **게이트 통과가 아니다** — 러너와 `resume.py` 가
   빠진 축을 같은 라운드에 병합하는 `--merge-into` 명령을 알려주고, 병합 후의 verdict 만
   판정이다. 유예된 축이 거기서 결함을 내면 NO-GO 로 돌아가는 것이 정상이다.

켜는 법: 라운드마다 `--lean` 을 붙이거나, `config.json` 에 `"moe": true` 를 저장하면
기본이 lean 이 된다(그때 `--full` 이 1회성 해제, `--reviewers` 명시가 최우선).
**기본은 꺼짐 — 전체 축이 기본값이다.** core 축은 `run_round.py` GATES 의 `core` 플래그로
정의된다(현재 `a-code`, `a-plan`). 계획 게이트는 2축뿐이라 실익이 없다 — 코드 게이트용이다.

절감 실측 근거: 코드 게이트 라운드당 리뷰어 비용에서 core(a-code) 외 4축이 약 70~80% 를
차지한다(report_usage 45라운드 집계 기준). 트레이드오프도 있다 — 유예된 축의 결함은 GO
후보 시점에 늦게 발견되므로 말미에 라운드가 1~2개 늘 수 있다. 총 호출 수는 그래도 줄고,
배정이 값을 하는지는 `report_usage.py` 로 사후 검증한다.

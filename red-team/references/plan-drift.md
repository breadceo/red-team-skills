# 구현 중 계획이 바뀌면 — 두 파일이 갈라지는 지점

> SKILL.md 의 「참고 문서」에서 참조된다. **구현 중 계획을 고치게 됐을 때, 또는
> `run_round.py` 의 계획서 신선도 경고(mtime)가 떴을 때 읽는다.**

`plan-*.md` 는 **구현자의 입력**이고 `context.md` 는 **리뷰어의 입력**이다. 둘은 별개
파일이라 갈라질 수 있고, 갈라지면 리뷰어가 낡은 기준으로 판정해 **조용히 틀린 GO** 가
난다. 구현 중 새 사실이 나와 계획을 고치는 것은 정상이지만, 무엇을 어디에 반영하는지는
갈라야 한다.

| 무엇이 바뀌었나 | 어디에 쓰나 |
|---|---|
| 개별 지적 반영 · pre-existing 을 후속 티켓으로 분리 | `decisions.md` — **자동 이관된다.** 손댈 필요 없다 |
| **판정 기준 자체** — 변경 의도, 불변식, 확인 사항(기획·정책), 스코프 경계 | `context.md` 를 **손으로 고친다** |
| 구현 순서 · 커밋 분할 · 파일 목록 | `plan-*.md` 만 |

두 번째가 자동화되지 않는 이유는 **무엇이 판정 기준인지는 사람이 정하는 것**이기 때문이다.
"이 불변식이 더 이상 유효하지 않다"는 판단을 스크립트가 대신할 수 없다.

그래서 `run_round.py` 가 **라운드 시작 시점에 mtime 을 비교해 경고**한다 —
같은 디렉토리의 계획서(`plan*.md`, 대소문자 무시하므로 `PLAN.md` 도 잡는다)가 `context.md`
보다 새로우면 알린다. 오탐이 나도 비용은 한 번 훑어보는 것이고, 놓치면 리뷰 전체가 낡은
기준 위에서 돈다. 경고가 뜨면 실제로 판정 기준이 바뀌었는지 보고, 바뀌었으면 `context.md`
를 갱신한 뒤 라운드를 다시 돌린다.
